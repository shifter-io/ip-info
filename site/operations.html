Run and deploy IP Info.

A Rust service, standalone website and private DB-IP database, packaged for Bunny Magic Containers.

Deployed on Bunny Magic Containers at https://ip-info.com on September 29, 2026. The image is in private GitHub Container Registry. GA4 and Search Console provisioning remain follow-up tasks.

Local start

cargo run --release --locked
# Open http://127.0.0.1:8080
curl -i 'http://127.0.0.1:8080/json?ip=8.8.8.8'

The default caller on localhost is a loopback IP and is intentionally rejected. Use a supplied public IP for local testing. Keep the server running to use the website’s lookup form. The static HTML files in web/ can be opened directly; under file URLs their lookup widget targets the production API.

Files and reproducibility

scripts/api_contract.py is the shared field/schema/example source. scripts/generate_site.py builds the standalone pages, OpenAPI, text references and Rust response type. Design sources are in site/. Generated pages are embedded into the binary; rebuild Rust after regenerating them.

python3 scripts/generate_site.py
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
# Private database acceptance tests:
cargo test --locked -- --include-ignored
npm ci
npm run test:browser

Browser tests use local Chrome on macOS when available; otherwise install Playwright Chromium with npx playwright install chromium. Local test dependencies are never needed in the production container.

Configuration

BIND_ADDR
Default 0.0.0.0:8080. Use 127.0.0.1:8080 for a host-only preview.
MMDB_PATH
Default data/dbip.mmdb; /data/dbip.mmdb in Docker. The file must remain immutable while mapped.
TRUSTED_PROXY_CIDRS
Comma-separated, verified ingress networks. Empty by default: forwarding headers are ignored. Never trust arbitrary private networks just because they are private. /0 is rejected.
CLIENT_IP_HEADER
Default x-forwarded-for. Walks the chain from the right through trusted hops. Other configured headers must contain exactly one IP and MUST be overwritten by Bunny ingress.
GA4_MEASUREMENT_ID
Optional G-… ID. Empty disables all Google scripts and collection. Only public pages integrate analytics.
SITE_INDEXABLE
Default false: all responses are noindex and robots.txt disallows crawling. Set true only for the production domain after completing launch checks. Lookup and health responses remain noindex.

The binary does not read .env automatically. Supply variables through your shell, Docker or Bunny. Docker Compose reads its variable substitutions from a local .env file.

Build and inspect the private container

docker build -t ip-info:local .
docker compose up -d
curl --fail http://127.0.0.1:8080/readyz
curl --fail 'http://127.0.0.1:8080/json?ip=8.8.8.8'
docker compose down
# Bunny commonly uses x86-64: build on this local device for its target.
docker buildx build --platform linux/amd64 --load -t ip-info:amd64 .

The image runs as UID/GID 10001 and works with a read-only root filesystem, no added capabilities and no writable volumes. The MMDB sits in its own image layer. Do not upload this commercial image to a public registry. Registry publishing is a separate launch action.

Bunny Magic Containers configuration

  1. Create a private registry entry and select the tested image digest. Preserve the digest for rollback.
  2. Expose the container’s HTTP port 8080 through an HTTP(S)/CDN endpoint. TLS terminates at Bunny; origin SSL is off.
  3. Attach ip-info.com, configure DNS as instructed by Bunny, and issue its managed certificate.
  4. Disable Force HTTPS and redirects for the API. Do not enable domain-wide HSTS if HTTP access must remain usable. HTTPS canonical tags are already present.
  5. Explicitly bypass caching for /json, /json?* and /*/json, including errors and redirects. Confirm no edge rule overrides Cache-Control: no-store. Bypass health endpoints too.
  6. Set readiness to GET /readyz on 8080 and liveness to GET /healthz. Allow at least 30 seconds startup grace for database initialization.
  7. Keep at least one replica active. Start evaluation with 1 vCPU and 2 GiB memory, then tune against measured working-set and tail-latency results. This is a starting configuration, not a performance guarantee.
  8. Configure a verified client-IP trust boundary as described below, and set the public GA4 ID only after its property is configured.
  9. Confirm production privacy details and logging behavior, then set SITE_INDEXABLE=true. Keep preview hosts unindexable.

Reference: Bunny deployment documentation. Account-side UI and headers must be verified at deployment; this package does not assume that every private source IP is Bunny.

Caller IP: production ingress

The deployed CDN overwrites X-IP-Info-Client-IP with its observed User.IP and sets X-IP-Info-Ingress to a private shared secret. The app verifies this against INGRESS_SECRET and rejects missing, duplicate, or invalid credentials for caller lookups. No trust-all CIDRs are configured. Production spoof tests passed. Rotate the CDN rule and application secret together; never expose this value in client code or logs.

Alternative CIDR-based deployments

The service must see the user’s actual network exit, not an edge proxy. Determine the exact peer source networks and header behavior of the chosen Bunny endpoint. Configure only those ingress CIDRs. With X-Forwarded-For, Bunny must append its observed caller or replace incoming untrusted values. With a single-IP header, Bunny must overwrite it.

Do not expose a second origin path that bypasses this trust boundary. Never configure a trust-all range or trust the leftmost X-Forwarded-For entry blindly. If Bunny cannot provide a verified boundary, keep self-detection unlaunched until one is configured; explicit-IP lookups can still be validated.

curl --fail https://ip-info.com/json
curl --fail -H 'X-Forwarded-For: 1.1.1.1' https://ip-info.com/json
curl --fail -H 'CDN-Real-IP: 1.1.1.1' https://ip-info.com/json
# All three must report the same real caller, not the forged IP.
# Repeat from a second network and via a Shifter proxy.
curl -i http://ip-info.com/json
# Must return JSON directly, no 301/302/307/308 redirect.

Database replacement and provenance

The licensed MMDB checksum and database type are recorded in data/source-manifest.json. Verify the checksum before building or replacing the database.

Never overwrite or truncate a file while a process maps it. Stop the local process first; copy a new release and update its manifest. Verify the checksum, run acceptance tests and build a new immutable image. Deploy that image with readiness checks and retain the prior image for rollback. No daily scheduler is included.

Startup validates database type, metadata and representative IPv4/IPv6 records. A decoding failure marks readiness unavailable. /healthz remains live so the platform can distinguish a running process from a ready database.

GA4 property setup and consent

  1. Create or choose an IP Info web stream and set GA4_MEASUREMENT_ID. No analytics requests occur without a valid ID and explicit consent.
  2. Disable ALL Enhanced Measurement in the stream, including page/history changes, outbound links, site search, downloads and forms. Automatic collection could otherwise capture URLs outside our event allowlist.
  3. Disable Google Signals, User-ID, advertising personalization and Ads links. Set event-data retention to two months and disable reset-on-new-activity. Record and verify these account settings before launch.
  4. Verify only sanitized page_view, code_copy, language_select, lookup_success and lookup_failure are intentionally sent. The client strips query/fragment information, uses an empty referrer, and never passes lookup fields.
  5. Test rejection, acceptance, withdrawal and a subsequent reload in a clean browser. Withdrawal disables collection immediately and reloads to remove Google-installed listeners.

Application cookies and preferences expire after at most 180 days. Google property retention is an account setting, not controlled by the binary. No claim of verified production analytics is made until these settings are confirmed.

Legal and privacy launch checks

The public Shifter policy verifies hi@shifter.io as a privacy contact: source. The public pages do not identify a verified full registered entity name/address. The included service-specific policies use the Shifter brand and verified contact; supply the operator details before final publication.

Confirm the actual Bunny edge/access-log settings and retention. The Rust application records startup state and database failures, not lookup IPs, raw paths or query strings. Disable optional edge request logging if it is unnecessary, or disclose its actual retention. Confirm that the commercial DB-IP subscription permits this public API use before launch. These account-specific facts must not be replaced with guessed claims.

Search Console launch

  1. Verify the ip-info.com domain in Google Search Console using its DNS TXT record.
  2. Set SITE_INDEXABLE=true only on production. Verify robots.txt allows crawling and the homepage no longer sends noindex.
  3. Submit https://ip-info.com/sitemap.xml. Inspect homepage, docs and AI guide canonical URLs and rendered HTML.
  4. Confirm HTTPS, canonical tags, share.png, favicon and all internal links. JSON and health endpoints must remain noindex.
  5. Monitor indexing and Core Web Vitals. Accurate metadata and crawlability do not guarantee ranking.

Benchmarks and smoke tests

python3 scripts/benchmark.py --base http://127.0.0.1:8080 --requests 3000 --workers 16
python3 scripts/smoke.py http://127.0.0.1:8080
# After deployment:
python3 scripts/smoke.py https://ip-info.com --production
python3 scripts/smoke.py http://ip-info.com --production
docker stats --no-stream ip-info-test
docker exec ip-info-test cat /sys/fs/cgroup/memory.stat

The benchmark uses many deterministic public IPv4 and IPv6 addresses and two passes, reporting throughput and p50/p95/p99. “First pass” is process-cold, not guaranteed OS-cache-cold: host filesystem pages may already be cached. Do not flush the host cache on this shared device. For genuinely cold-page measurements use a fresh isolated local VM/container host and record that condition.

Measure total cgroup memory and file-backed pages alongside RSS and CPU. A 1.3 GB memory map is not free physical memory: varied traffic can grow the resident working set. Repeat under the intended deployment CPU/memory limit before committing capacity.
