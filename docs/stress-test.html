After the 20-second cooldown, RSS was 355.4 MiB. Memory-mapped database pages and allocator retention can keep RSS above the initial 3.7 MiB; RSS alone does not establish a heap leak.

Test conditions

  • Private 1.3 GB DB-IP MMDB; native release server bound only to 127.0.0.1:18080. Client and server share the device. The report combines the initial concurrency sweep and a separate restarted process for the soak and diagnostic follow-ups. The memory chart shows only the follow-up process.
  • Varied workload uses deterministic, changing public IPv4 and IPv6 addresses. Hot workload repeats 8.8.8.8. Mixed workload combines lookups, HTML pages and expected 400 responses. Churn opens a new connection per request.
  • Each worker has one request in flight. This is a closed-loop saturation test, not a fixed-arrival-rate capacity test. Higher concurrency can increase queueing latency.
  • Checks cover response status and, for successful lookups, parsed IP identity. Expected missing records (404) and intentional invalid input (400) are not server failures.
  • All seven functional tests passed, including the two opt-in tests against the private database. Readiness probe results are recorded in the raw data; connection churn may exhaust client ports and prevent probes. Server exit: 0.

Assessment

High keep-alive throughput passed at moderate concurrency. At 512 connections, connection resets reproduced; this is an overload limitation. The two-minute soak had no errors, but RSS continued to rise as varied lookups touched the memory-mapped database, so this test does not establish a memory plateau or exclude a leak. Churn errors caused by exhausted local source ports are a load-generator/host limit and cannot be treated as server capacity.

What these results do and do not establish

The measured workloads exercise high local throughput and short sustained resource behavior. They do not establish a maximum production RPS or rule out long-running leaks. No TLS, remote network, container memory/CPU limits, ingress, HTTP/2 load, multi-hour soak, or connection-exhaustion test was included. Host cache may already be warm.

Code inspection also shows no global accepted-connection cap in the server. Per-connection HTTP/2 stream and header limits exist, but total concurrent connections still need bounding at ingress or in the server for public overload protection.
